  <files>pages/api/admin/data-map/playground.ts</files>
  <action>
Create `pages/api/admin/data-map/playground.ts` as a POST-only admin endpoint.

**Auth:** Use `handlerWithUser()` from `lib/middleware/handler` + `checkIsUpstream(req.user.orgId)` — same pattern as all other admin data-map routes.

**Request body:** `{ apiKeyId: string; mode: 'validate' | 'ingest'; payload: { client_id, date_min, date_max, events } }`

**Validation (both modes):**
1. Body check: `apiKeyId`, `mode`, `payload` present; `mode` is 'validate' or 'ingest'
2. Payload check: `client_id` non-empty string, `date_min`/`date_max` parseable ISO dates, `dateMin <= dateMax`, `events` is non-empty array
3. API key lookup: `prisma.rspApiKey.findUnique({ where: { id: apiKeyId }, include: { org: true } })` — return 404 if not found; return 400 if `!key.isActive` or `key.org.orgType !== 'reuse-service-provider'`

Collect validation results as an array of `{ name: string; passed: boolean; message?: string }` checks:
- `{ name: 'client_id present', passed: !!client_id }`
- `{ name: 'date_min valid', passed: !isNaN(dateMinParsed.getTime()) }`
- `{ name: 'date_max valid', passed: !isNaN(dateMaxParsed.getTime()) }`
- `{ name: 'date order', passed: dateMinParsed <= dateMaxParsed }`
- `{ name: 'events non-empty', passed: events.length > 0 }`

**Validate mode:** After collecting validation checks, query overlapping periods (same query as ingestUsagePeriod uses — active periods for this org + client_id that overlap the date range). Return without writing to DB:
```json
{ "mode": "validate", "valid": true/false, "checks": [...], "overlapCount": N, "overlappingPeriodIds": ["..."] }
```

**Ingest mode:** If all validation checks pass, look up account (`prisma.account.findFirst({ where: { rspOrgId: key.orgId, rspClientId: client_id } })`), then call `ingestUsagePeriod({ orgId: key.orgId, clientId: client_id, dateMin: dateMinParsed, dateMax: dateMaxParsed, events, submittedByKeyId: key.id, accountId: account?.id ?? null, rawPayload: payload })`. Return:
```json
{ "mode": "ingest", "newPeriodId": "...", "overlappingCount": N, "metrics": { ... } }
```
If validation fails in ingest mode, return 400 with `{ error: 'Payload validation failed', checks }`.

On ingestUsagePeriod error: return 500 with `{ error: err?.message }`.
