  <name>Task 1: Create pages/admin/data-science/inputs/index.tsx</name>
  <files>pages/admin/data-science/inputs/index.tsx</files>
  <action>
    Create the Data Inputs page. This page has NO data in `getServerSideProps` — it is auth-only. All data comes from a client-side POST to `/api/admin/data-health/scan` on mount.

    **Component structure:**
    - `getServerSideProps`: auth-only (same pattern as other admin pages — see interfaces block)
    - `selectedMenuItem='data-science/inputs'` on AdminLayout (nav already wired from Phase 1)
    - Page title: "Data Inputs" (Typography Title level={2})
    - Subtitle: "Scan project data for quality issues, discrepancies, and unlikely values." (Paragraph type='secondary')

    **State:**
    ```typescript
    const [issues, setIssues] = useState<DataHealthIssue[]>([]);
    const [scanning, setScanning] = useState(false);
    const [lastScanAt, setLastScanAt] = useState<Date | null>(null);
    const [validateModal, setValidateModal] = useState<{ open: boolean; issue: DataHealthIssue | null }>({ open: false, issue: null });
    const [note, setNote] = useState('');
    const [saving, setSaving] = useState(false);
    ```

    **runScan function** (wrapped in `useCallback`, called by `useEffect` on mount AND by Re-scan button):
    ```typescript
    const runScan = useCallback(async () => {
      setScanning(true);
      try {
        const res = await fetch('/api/admin/data-health/scan', { method: 'POST' });
        const data = await res.json();
        setIssues(data);
        setLastScanAt(new Date());
      } finally {
        setScanning(false);
      }
    }, []);

    useEffect(() => { runScan(); }, [runScan]);
    ```

    **Issue description map** (human-readable descriptions per issueType):
    ```typescript
    const ISSUE_DESCRIPTIONS: Record<string, string> = {
      missing_us_state: 'Project has no US state set — utility rates and emission factors require a state',
      missing_single_use_items: 'Project has no single-use line items — calculations will produce zero results',
      missing_reusable_items: 'Project has no reusable line items — calculations will produce zero results',
      zero_unit_line_item: 'Single-use line item has unitsPerCase = 0 — will produce division by zero in calculations',
      return_rate_over_100: 'Reusable line item has annual repurchase percentage > 100% — unlikely value',
      reusable_negative_case_cost: 'Reusable line item has a negative case cost — check for data entry error',
      unrealistic_case_cost: 'Reusable line item case cost exceeds $1 billion — likely a data entry error',
      single_use_negative_case_cost: 'Single-use line item has a negative case cost — check for data entry error',
      negative_quantity: 'Reusable line item has a negative quantity (casesPurchased < 0) — check for data entry error',
    };
    ```

    **Column definition** (single ColumnsType<DataHealthIssue> used for both tables):
    Columns in order: Issue Type (code text), Entity, Entity ID (truncated, secondary text), Description, Severity (Tag: red for error, orange for warning), Status (Tag: blue/processing for open, green/success for acknowledged), Actions.

    Actions column: show a "Validate" primary small Button only when `row.status === 'open'`. When acknowledged, show nothing (or a small "Acknowledged" text in muted color).

    **Two-section layout:**
    ```
    errors = issues.filter(i => i.severity === 'error')
    warnings = issues.filter(i => i.severity === 'warning')
    ```

    Wrap in `<Spin spinning={scanning}>`. When not scanning and issues.length === 0, show the empty state instead of tables.

    Empty state: centered div with `<CheckCircleOutlined style={{ color: '#52c41a', fontSize: 48 }} />`, then "No issues detected — data looks healthy" in Title level={4} muted color.

    For the two sections, show a `<Title level={4}>` section header ("Errors ({N})" and "Warnings ({N})") before each Table. Only render an errors Table section if `errors.length > 0`, same for warnings. This avoids showing empty sections after a clean scan.

    **Re-scan button** (top right of page, next to page title area):
    ```typescript
    <Button
      icon={<ReloadOutlined />}
      onClick={runScan}
      loading={scanning}
    >
      {lastScanAt ? `Re-scan (last: ${lastScanAt.toLocaleTimeString()})` : 'Re-scan'}
    </Button>
    ```

    **Validate modal:**
    - Opens when "Validate" clicked: `setValidateModal({ open: true, issue: row })`
    - Title: "Validate Issue"
    - Body: show issue type, entity, entity ID, description, severity badge
    - Below: `<Input.TextArea placeholder="Optional note — describe what you checked or why this is acceptable" rows={3} value={note} onChange={e => setNote(e.target.value)} />`
    - Footer: standard OK/Cancel + a Link "Create Change Request →" that opens `/admin/data-science/change-requests` in a new tab
    - On OK (confirm handler):
      ```typescript
      setSaving(true);
      try {
        const res = await fetch(`/api/admin/data-health/issues/${validateModal.issue!.id}`, {
          method: 'PATCH',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({ status: 'acknowledged', note })
        });
        const updated = await res.json();
        setIssues(prev => prev.map(i => i.id === updated.id ? updated : i));
        setValidateModal({ open: false, issue: null });
        setNote('');
      } finally {
        setSaving(false);
      }
      ```
    - On Cancel: `setValidateModal({ open: false, issue: null }); setNote('');`
    - `confirmLoading={saving}` on Modal

    Import `Input` from antd for the TextArea. Import `DataHealthIssue` type from `@prisma/client`.

    Do NOT use `useSWR` — plain `useState` + `fetch` is correct for this triggered-action pattern (per RESEARCH.md).
